# 工作台角色/剧本/分镜：暗壳 + 浅色印张

## Problem

WPF 主栏是暗底堆叠文本，既对不上参考 HTML 的阅读骨架，也没用上五份 Markdown 已解析字段。参考报告里多出来的钩子、关系、台词簿、质量门、导出、时长仪、批次与音频表，项目里原先没有对应契约。

## Decision

主窗保持暗金 chrome，只有 `MainHost` 铺冷灰印张（`PaperViews.cs`）。字段仍来自 `creator_views.py` 与 `/api/episode`，不另造 `cast.json`。

角色/美术：花名册（搜索、人物/造型或地点/道具分轨、76px 空切片）+ 16:9 图位 + 识别锚点/本集状态/声音方向/连续性锁。可选阅读卡 `关系`、`性情`、`动机`、`弧光`、`原文依据` 写在人物条目下，分镜核对不读。关系图画成列表边，不是 SVG。

剧本：本集 KPI、可选 `开场钩：`/`集末悬念：`（标题与第一场之间）、场次芯片、对白三列与复制、角色台词簿。时长仪用对白字数/4 + 动作段×2s，对照系列目标。

分镜：时长×景别节奏条、两列镜卡（起始帧 REF 或占位、起/动/终、视觉依据、冻结关键帧/MOTION/声音页签）。本集图片提示词当生成条目墙；剪辑单字幕当音频对齐。

新增项目能力：`parse_screenplay` 的 hook/cliff/lineBook；`metrics` 的 scriptEst；`quality_gate`（审查 must=0 为通过）；`relation_graph`；主栏「导出 JSON」写入 `项目开发/<EP>-视图.json`（阅读快照，不是创作真相）。概况页增加全剧时长条。质量门读已有审查 findings。

## Alternatives considered

- **只改配色、结构仍三张卡片**：最强理由是快。不用：和参考、五文档都对不上。
- **整页嵌入三份 HTML + 导出第二套 JSON 真相**：最强理由是零差距。不用：工作室按集工作，Markdown 仍是唯一创作源；导出只做快照。
- **把性情/动机/弧光当成识别锚点**：最强理由是栏目和小说报告一致。不用：它们是可选阅读卡，身份仍以识别锚点为准。
- **关系图谱做成 SVG 力导向**：最强理由是更像报告。不用：边少时列表更稳，且不引入新依赖。

## Consequences

写剧本时可补钩子两行；写人物时可补关系与阅读卡，不写则主栏留空。印张前景必须显式用 Print/Seal，不能靠窗体隐式奶油色 TextBlock。预览 HTML 可对照，非正式 UI。
