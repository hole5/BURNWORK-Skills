# Agent Note: 生产模式、会话自动生产与小烧改本机配置

Status: proposed（已落地，见 [implemented](../../implemented/architecture/2026-10-08-produce-mode-and-config-agent.md)）

## Problem

工作室已能聊天路由 skills 写五文档，但出图出视频必须在「生产」页确认；创作者希望可选「确认后交给小烧跑完」，并希望聊天协助配置 API / ComfyUI / 云端。若只靠提示词约束，模型可能临场越权；若默认全自动，易误花算力与密钥风险。

## Proposal

分两阶段落地，**限制一律写死在配置位 + API 拦截**，提示词只说明。

### 阶段 A — 设置页「生产模式」（优先）

持久化到项目外配置（建议 `~/.mochang/produce.json` 增加 `mode`，与现有 adapter 并列；聊天会话授权另存运行时状态）。

三档单选，默认 **确认闸门**：

1. **确认闸门（默认）**  
   - 聊天只允许 `prepare_produce`  
   - `confirm_produce` / `run_produce` 服务端直接拒绝，固定文案引导去「生产」页  
2. **会话授权自动**  
   - 本会话内用户点一次「允许小烧自动生产」后，才开放 confirm/run  
   - 关程序、切手动档、点「撤销授权」立即失效  
3. **始终自动（高风险）**  
   - 设置里二次确认后才可勾选  
   - 点名出图/出视频时可 prepare→confirm→run  
   - 仍按批次回报，不静默无限跑

**每次 run 前强制环境检查（写死）**：聊天 API 可用；出图 adapter 已保存并启动；出视频 adapter 已保存并启动。缺什么只返回检查结果，不提交任务。

「连续写文档」继续只覆盖 Markdown，**不等于**自动生产。

设置 → 生产：展示三档、风险说明、API/出图/出视频状态灯、会话授权状态与撤销。

### 阶段 B — 小烧改本机配置（推荐，默认关）

设置增加 **「允许小烧改本机配置」**（默认关）。开启后，聊天可提议修改 `~/.mochang` 内聊天 profile、ComfyUI / MiniMax H3 / 云端出图出视频等；**每次写入前预览 diff，用户确认后落盘**。

边界：

- 只改本机配置，不改程序 exe/源码，不装 Cursor MCP  
- 密钥可写配置文件，界面预览默认脱敏  
- 未开此开关时，相关 tool 直接拒绝

### 展示层（非安全边界）

开场问候、`need_confirm`、缺配置提醒按当前模式切换文案；真正能不能跑以服务端模式位与检查结果为准。

## Alternatives considered

- **只改系统提示词让模型别自动生产** — 最强理由：零工程。不用：不可靠，与现有「写死禁止 confirm」原则冲突。  
- **默认始终自动** — 最强理由：最省事。不用：误触与费用风险高。  
- **聊天永久可改配置且无确认** — 最强理由：上手最快。不用：密钥与后端地址敏感。  
- **配置能力与生产模式捆绑成一个开关** — 最强理由：设置更简单。不用：写文档代理与改本机配置风险等级不同，应分开。

## Consequences

- **收益**：默认仍安全；进阶用户可会话/始终自动生产；配置协助降低设置门槛。  
- **代价**：设置与 agent 工具面变复杂；需维护模式位、会话授权与配置预览确认 UI；正式对外前应用例覆盖三档拦截。
